---
title: Train from Files
api: POST /v1/chatbots/{chatbot_id}/training/files
description: Upload files for training (multipart or base64)
---

Requires `training:write` scope. Max 20 files per request, 50 MB per file. Supported formats: CSV, PDF, TXT, JSON.

**Two upload methods are available:**
- **Multipart** — `POST /v1/chatbots/{id}/training/files` with `Content-Type: multipart/form-data`
- **Base64** — `POST /v1/chatbots/{id}/training/files/base64` with a JSON body

Both endpoints return `202 Accepted` with a `session_id` for polling status.

**Deduplication:** Files are automatically deduplicated by content hash (SHA-256). If an identical file was already uploaded to the same chatbot and is pending, processing, or completed, it is skipped. Duplicate files appear in the `rejected_files` array with a reason.

<ParamField path="chatbot_id" type="string" required>
  The chatbot ID.
</ParamField>

## Multipart upload

<ParamField body="files" type="file[]" required>
  One or more files to upload.
</ParamField>

<ParamField body="chatbot_id" type="string" required>
  Must match the path parameter.
</ParamField>

<ParamField body="chunking_strategy" type="string" default="auto">
  How to split content: `auto`, `individual`, or `semantic_groups`.
</ParamField>

<ParamField body="custom_metadata" type="string">
  JSON string of metadata tags attached to every chunk. Used for filtering at query time.

  If your chatbot has variables with `auto_filter` enabled, include the variable values here so data is tagged for per-user isolation:

  ```
  {"user_id": "alice"}
  ```

  See [Multi-User Isolation](/guides/multi-user-isolation) for details.
</ParamField>

## Base64 upload

<ParamField body="files" type="array" required>
  Array of file objects with `filename` and `content_base64` (base64-encoded file content).
</ParamField>

<ParamField body="chunking_strategy" type="string" default="auto">
  How to split content: `auto`, `individual`, or `semantic_groups`.
</ParamField>

<ParamField body="custom_metadata" type="object">
  Optional metadata tags attached to every chunk created from these files. Used for filtering at query time.
</ParamField>

<RequestExample>
```bash cURL (multipart)
curl -X POST https://api.cleveract.ai/v1/chatbots/bot_abc123/training/files \
  -H "X-API-Key: ak_live_YOUR_KEY" \
  -F "chatbot_id=bot_abc123" \
  -F "files=@faq.csv" \
  -F "files=@guide.pdf" \
  -F "chunking_strategy=auto"
```

```bash cURL (base64)
curl -X POST https://api.cleveract.ai/v1/chatbots/bot_abc123/training/files/base64 \
  -H "X-API-Key: ak_live_YOUR_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "files": [
      {
        "filename": "faq.csv",
        "content_base64": "UXVlc3Rpb24sQW5zd2VyCiJXaGF0IGlzIENsZXZlckFjdD8iLCJBbiBBSSBjaGF0Ym90IHBsYXRmb3JtIg=="
      }
    ],
    "chunking_strategy": "auto"
  }'
```

```bash cURL (with metadata for per-user isolation)
curl -X POST https://api.cleveract.ai/v1/chatbots/bot_abc123/training/files/base64 \
  -H "X-API-Key: ak_live_YOUR_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "files": [
      {
        "filename": "alice-docs.pdf",
        "content_base64": "base64_encoded_content_here..."
      }
    ],
    "custom_metadata": { "user_id": "alice" }
  }'
```
</RequestExample>

<ResponseExample>
```json 202 Accepted
{
  "status": "accepted",

  "chatbot_id": "bot_abc123",

  "rejected_files": []
}
```

</ResponseExample>
